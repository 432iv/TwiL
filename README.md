# يوسف للعطور — Yousef Perfumes

منظومة متكاملة لإدارة **محل عطور**: عطور مغلقة بالقطعة، وعطور مفتوحة للتقسيم بالمليلتر،
وعبوات تقسيم بمخزون وتكلفة وسعر مستقلّين، مع **فواتير ومرتجعات · مشتريات بمتوسط تكلفة مرجّح ·
مصروفات · صندوق نقدي · جرد · تقارير أرباح · إغلاق يومية مجمّدة (وإعادة فتحها) · باركود متعدد
وبيع سريع · نسخ احتياطي/استرجاع**.

المشروع يعمل بإحدى طريقتين مع الإبقاء على واجهته وBackend الحاليين:
- **Desktop Offline (Windows):** Electron يشغّل Express محليًا، وقاعدة PostgreSQL مضمّنة عبر PGlite تُحفظ على القرص. لا تحتاج النسخة المثبّتة إلى إنترنت أو PostgreSQL/Node.js منفصل.
- **وضع الخادم الحالي:** Express + PostgreSQL عبر `DATABASE_URL` كما كان للمطور أو للاستضافة.

الواجهة عربية RTL بهوية **بيج / بني ناعم** (فاتح افتراضياً وداكن بني اختياري). بيانات Desktop تبقى خارج مجلد تثبيت البرنامج، فلا تُحذف عند التحديث.

## 1. فكرة النظام (العطور المغلقة والمفتوحة والعبوات)

| المخزون | الوحدة | الحقل | التكلفة |
|---|---|---|---|
| **علب مغلقة** | قطعة | `products.quantity` | `purchase_price` (متوسط مرجّح من المشتريات) |
| **مل مفتوحة للتقسيم** | مل | `products.open_ml` | `open_cost_per_ml` (متوسط مرجّح، قابل للتعديل يدوياً) |
| **عبوات التقسيم** | قطعة | `vials.quantity` | `vials.cost` (متوسط مرجّح من المشتريات) |

- **سعر العلبة المغلقة (`sale_price`) مستقل تماماً عن سعر المل (`ml_price`)** — تغيير أحدهما لا يمس الآخر.
- **تخصيص للتقسيم**: يحوّل `N` علب مغلقة إلى `N × الحجم الأصلي` مل مفتوحة.
  مثال: 5 علب (100 مل) ← علبة واحدة للتقسيم ← **4 مغلقة + 100 مل مفتوحة**.
  تكلفة المل = تكلفة العلبة ÷ حجمها، وتُدمج بمتوسط مرجّح مع الرصيد المفتوح،
  ويمكن تعديل تكلفة العلبة عند التخصيص أو تكلفة المل لاحقاً. تُسجَّل العملية في
  `open_operations` وفي حركة المخزون (خروج مغلق + دخول مفتوح بسبب `open_split`).
- **بيع التقسيم**: `السعر = مل × سعر المل + عدد العبوات × سعر العبوة`.
  مثال: 10 مل × 3 + عبوة 10 مل بـ 1.5 = **31.5 د.ل**. يُخصم المل من الرصيد المفتوح وعبوة من
  مخزون العبوات، ويحفظ البند: العطر، المل المباع، سعر المل، العبوة ونوعها وتكلفتها وسعرها.
  التكلفة = `مل × تكلفة المل + عدد العبوات × تكلفة العبوة`، فيُحسب الربح بدقة.
  كميات سريعة 5/10/20/30/50 مل أو إدخال يدوي، محدودة بالمتاح؛ ويُختار حجم العبوة تلقائياً.
- **التصنيفات صيفية / شتوية فقط** (يفرضها قيد في القاعدة: `categories.code IN ('summer','winter')`).
- **الجرد** يفصل: علب مغلقة (قطع) · مل مفتوحة · عبوات (قطع).
- المرتجع يعيد (بخيار) المل والعبوة للمخزون؛ وإن لم يُعَد يبقى أثر التكلفة خسارة في الربح.

## 2. المعمارية

**نسخة Desktop المثبّتة:**

```
Electron (نافذة Windows آمنة)
        │ http://127.0.0.1 على loopback فقط — يبدأ تلقائياً ويُغلق مع البرنامج
        ▼
server/index.js  ── Express API الحالي + migrations الحالية
        │ db.js adapter
        ▼
PGlite (PostgreSQL داخل Node/WASM) ── %APPDATA%\\YousefPerfumes\\database
```

أما التشغيل السحابي/التطوير القديم فيستخدم `pg` وPostgreSQL عبر `DATABASE_URL`. اختيار قاعدة البيانات لا يغير منطق المسارات أو المخزون أو التقارير؛ `server/db.js` هو طبقة التبديل المشتركة.

| المسار | الوظيفة |
|---|---|
| `electron/main.js` | تشغيل Backend وقاعدة PGlite تلقائياً، إنشاء نافذة Desktop، حفظ نسخة عبر نافذة Windows، ومنع التنقل للخارج |
| `yousef-perfumes.html` | الواجهة الحالية كاملة، وتستدعي API محلياً في Desktop |
| `server/index.js` | Express API، تقديم الواجهة، المهاجرات عند بدء البرنامج وتحديد CSP محلي |
| `server/config.js` · `server/db.js` | وضع PostgreSQL الحالي أو PGlite المحلي مع واجهة `query()`/`tx()` نفسها |
| `server/migrate.js` | ترقية المخطط بأمان عند كل تشغيل؛ المهاجرات المنفذة لا تعاد |
| `server/routes/` و`server/lib/` | منطق النظام الحالي؛ لم يُستبدل بBackend جديد |
| `server/migrations/` | مخطط PostgreSQL المشترك بين وضع الخادم وPGlite |
| `resources/app.ico` | أيقونة مثبت Windows وملف التطبيق التنفيذي |
| `assets/app.ico` · `assets/app.png` | أيقونة النافذة داخل البرنامج بعد التثبيت |
| `tests/offline.test.js` | اختبار API على قاعدة PGlite مؤقتة ثم التحقق من بقاء البيانات بعد إغلاق وإعادة فتح Backend |

## 3. التشغيل والتثبيت

### استخدام Desktop أثناء التطوير (Windows)

يلزم على **جهاز التطوير فقط**: Windows 10/11 x64 وNode.js `22.12+` وnpm. لا تثبّت PostgreSQL.

```powershell
npm ci
npm run desktop
```

يفتح البرنامج مباشرة بقاعدة PGlite محلية تجريبية في `.desktop-dev\\database` داخل المشروع. الحساب والبيانات التجريبية منفصلان عن أي نسخة مثبتة.

### بناء ملف التثبيت النهائي

من Windows x64:

```powershell
npm ci
npm run build:win
```

ينتج الملف `release\\Yousef-Perfumes-Setup-1.0.0.exe` (قد يتغير رقم الإصدار حسب `package.json`). شغّله على اللابتوب المطلوب للتثبيت؛ ينشئ اختصاراً على سطح المكتب وقائمة ابدأ ويشغّل التطبيق. جهاز المستخدم النهائي **لا يحتاج Node.js أو npm أو PostgreSQL أو اتصال إنترنت**. يُنصح ببناء نسخة Windows على Windows نفسه. إن كانت النسخة غير موقّعة بشهادة ناشر فقد يعرض Windows SmartScreen تنبيهاً عند التثبيت.

### ترحيل بيانات محل موجود

من النظام الحالي: **الإعدادات ← تنزيل نسخة احتياطية**. ثبّت وافتح نسخة Desktop، أنشئ بيانات دخول محلية أول مرة، ثم اختر **الإعدادات ← استرجاع نسخة** وحدد ملف JSON. تُسترجع المبيعات والمخزون والمشتريات والمصروفات والصندوق والتقارير والإعدادات؛ يبقى حساب الدخول المحلي الذي أنشأته في البرنامج. لا تُرفع البيانات إلى أي خادم.

### وضع PostgreSQL/الخادم الحالي للمطور

```bash
cp .env.example .env    # عدّل DATABASE_URL وSESSION_SECRET
npm ci
npm run migrate
npm run dev             # PostgreSQL + Backend للتطوير
# أو npm start
```

`npm run desktop` لا يقرأ اتصال PostgreSQL الموجود في `.env`؛ Desktop يفرض PGlite محلياً. تبقى أوامر Web/الخادم لاستخدام المشروع الحالي دون تغيير.

أوامر مساعدة:

```bash
npm run seed            # بيانات تجريبية — تمسح بيانات القاعدة الحالية، الحساب يبقى
npm run wipe            # تصفير كل البيانات (WIPE_PASS=... لتحديد كلمة المرور)
npm test                # فحوص API على خادم PostgreSQL يعمل
npm run test:offline    # API كامل على قاعدة PGlite مؤقتة + تحقق من الاستمرارية بعد إعادة التشغيل
npm run test:e2e        # فحوص المتصفح (تتطلب Playwright وChromium للتطوير فقط)
npm run screens         # لقطات شاشة لكل الصفحات → screens/
```

**أول تشغيل:** تظهر شاشة *الإعداد الأول* وتطلب اسم مستخدم وبريدًا وكلمة مرور — هذا هو
الحساب الوحيد. بعدها لا يظهر إلا تسجيل الدخول.

> **ترقية من نظام «Blue Mobile» القديم (هواتف):** المهاجرة `007` تحذف جداول/أعمدة الهواتف
> (IMEI، الموديل، اللون، السعة) وتحوّل التصنيفات إلى صيفية/شتوية. لمحل جديد ابدأ بقاعدة جديدة
> أو استخدم `npm run wipe`. نسخ JSON القديمة (هواتف) تُرفض عند الاسترجاع برسالة واضحة.

## 4. الوحدات

- **الرئيسية** — مبيعات وأرباح اليوم، عدد الفواتير، المصروفات، رصيد الصندوق، قيمة المخزون،
  المل المفتوحة، الأكثر مبيعاً (30 يوماً)، النواقص (عطور وعبوات)، العطور المفتوحة للتقسيم
  والمل المتبقي، ملخص مغلق/تقسيم، آخر عمليات البيع والشراء، ملخص الصندوق.
- **المبيعات** — فواتير `INV-xxxxx` متعددة الأصناف: سطر لكل عطر بنوعين (علبة مغلقة / تقسيم بالمل)،
  بند حر، خصم، نقد/بطاقة/غير خالص، تعديل وإلغاء وإرجاع وحذف، طباعة فاتورة.
- **المخزون** — العطور (ماركة، حجم، نوع، صيفية/شتوية، باركودات، أسعار، السماح بالتقسيم، رصيد
  مغلق ومفتوح) · عبوات التقسيم · سجل عمليات التقسيم · حركة المخزون الموحّدة (مغلق/مفتوح/عبوات)
  · الجرد.
- **المشتريات** — فواتير `PUR-xxxxx`: عطور مغلقة (للرصيد المغلق) أو عبوات (لمخزون العبوات)،
  إنشاء عطر/عبوة جديدة من داخل الفاتورة، متوسط تكلفة مرجّح، مدفوعة أو آجلة، تعديل وإلغاء.
- **المصروفات · الصندوق** — كما في الأصل، مربوطان باليوم والأرباح.
- **التقارير** — الأيام المغلقة (لقطة مجمّدة + **إعادة فتح اليوم**) · المبيعات (حسب اليوم/العطر/
  طريقة الدفع/نوع البيع/حجم التقسيم) · **العطور والتقسيم** (مغلق، تقسيم، مل مباعة، العبوات
  تكلفةً ومبيعاتٍ، حسب العطر وحسب الحجم، عمليات التخصيص، المشتريات والمصروفات والصافي)
  · الأرباح والخسائر · المخزون (مغلق مقابل مفتوح، عبوات، نواقص، راكد).
- **الإعدادات** — بيانات المحل والشعار، العملة، الحد الأدنى، طرق الدفع، حساب وكلمة مرور وجلسات،
  نسخ احتياطي/استرجاع، **البيع السريع بالباركود** و**وضع تسجيل العطور بالباركود** (باركودات متعددة).

## 5. قاعدة البيانات (مختصر)

`users · sessions · settings · payment_methods · categories(summer|winter) · products ·
product_barcodes · vials · vial_movements · open_operations · invoices · invoice_items ·
sale_returns · purchases · purchase_items · expenses · cash_movements · stock_movements ·
stocktakes · stocktake_items · days · day_summaries · notes · product_names` + العرض `split_sales`.

- `invoice_items.sale_type = 'sealed' | 'split'` — بند التقسيم يخزّن `ml_qty, ml_price, ml_cost,
  vial_id, vial_name, vial_size_ml, vial_qty, vial_cost, vial_price`.
- أعمدة `GENERATED ALWAYS` للإجماليات — الحساب لا ينحرف. الكمية والمل والعبوات لا تنزل تحت الصفر.
- إلغاء/حذف/تعديل عملية **يعكس** كل آثارها (مغلق + مفتوح + عبوات + صندوق).
- المهاجرات الجديدة فقط تُضاف (`008_…` وما بعدها)؛ لا تُعدَّل المهاجرات المطبَّقة.
  ملاحظة: ملفات `001–006` تاريخية وتذكر مفاهيم الهواتف لأنها تبني الأساس ثم تحوّله `007`.

## 6. الـ API

كل المسارات تحت `/api` وما عدا `/api/auth/*` و`/api/health` تتطلب جلسة (401 بدونها).

| المجموعة | المسارات |
|---|---|
| المصادقة | `GET auth/status` · `POST auth/setup|login|logout|password` |
| الأيام | `GET days` · `GET days/current` · `POST days` · `GET days/:id` · `POST days/:id/close` · **`POST days/:id/reopen`** · `DELETE days/:id` |
| المبيعات | `GET sales` · `POST sales` (بند `mode:"split"` للتقسيم) · `PUT|DELETE sales/:id` · `POST sales/:id/cancel` · `POST sales/:id/returns` (`restock`) |
| المخزون | `GET inventory` · `GET|POST inventory/products` · `PUT|DELETE inventory/products/:id` · `POST inventory/products/:id/adjust` (`target: sealed|open`) · **`POST inventory/products/:id/open-split`** · `GET inventory/open-operations` · `GET inventory/search` · `GET inventory/barcodes` · `POST inventory/barcode-batches` · `GET inventory/movements` (`kind`) · `GET inventory/categories` · `POST|GET inventory/stocktakes` |
| العبوات | `GET|POST inventory/vials` · `PUT|DELETE inventory/vials/:id` · `POST inventory/vials/:id/adjust` |
| المشتريات | `GET|POST purchases` (عطر أو `type:"vial"`) · `GET|PUT|DELETE purchases/:id` · `POST purchases/:id/cancel` |
| المصروفات | `GET|POST expenses` · `PUT|DELETE expenses/:id` |
| الصندوق | `GET cashbox` · `POST cashbox/deposit|withdraw` · `DELETE cashbox/movements/:id` |
| التقارير | `GET reports/dashboard` · `reports/sales?group=day\|product\|method\|type\|size` · `reports/perfumes` · `reports/pnl` · `reports/inventory` |
| الحساب | `GET bootstrap` · `GET|PUT settings` · `GET|PUT payment-methods` · `GET backup` · `POST backup/restore` · `DELETE data` |

العمليات تُرفض على يوم مغلق (`409 day_closed`) وبدون يوم مفتوح (`409 no_open_day`)،
والقراءة تعمل دائمًا. التصنيفات للقراءة فقط (`403 categories_fixed` عند محاولة التعديل).

## 8. ملاحظات تشغيلية وOffline

- تصفير البيانات مع إبقاء الحساب: زر *حذف جميع البيانات* في الإعدادات، أو `npm run wipe` (في وضع الخادم).
- إعادة ضبط كاملة في PostgreSQL (يمسح الحساب أيضًا): `psql "$DATABASE_URL" -c "TRUNCATE users CASCADE;"`.
- نسخة JSON الاحتياطية تشمل جداول النظام، والاسترجاع يتم داخل معاملة واحدة. في Desktop زر النسخ الاحتياطي يفتح نافذة Windows **حفظ باسم**، والاسترجاع يفتح نافذة اختيار ملف.
- قاعدة Desktop محفوظة على جهاز المستخدم في `%APPDATA%\\YousefPerfumes\\database` (المسار الفعلي عبر `app.getPath('userData')`)، وليست داخل مجلد تثبيت البرنامج. بيانات الدخول السرية ومنفذ الخدمة المحلي بجانبها.
- عند التحديث، تُطبّق migrations الجديدة دون حذف الجداول القائمة؛ إعداد NSIS لا يحذف مجلد بيانات المستخدم حتى عند إزالة البرنامج. خذ نسخة احتياطية قبل تحديث رئيسي.
- قارئ الباركود الحالي يعمل محلياً كقارئ USB/HID يكتب رقم الباركود في الحقل؛ مطابقة المنتج وتحديث البيع والتسجيل كلها من قاعدة الجهاز ولا تستخدم خدمة أو API خارجية.
- الخط العربي مضمّن داخل HTML. **تسجيل الدخول عبر Google هو الميزة الوحيدة التي تتطلب إنترنت**؛ يُخفى ويُرفض صراحةً في Desktop Offline، ويُستخدم اسم المستخدم وكلمة المرور المحليان.
- التشغيل المثبّت لا يستدعي CDN أو خدمة استضافة أو سيرفر خارجي؛ Express مرتبط على `127.0.0.1` ويبدأ ويُغلق تلقائياً مع نافذة البرنامج. تعطل الإنترنت لا يمنع البيع أو البحث أو النسخ الاحتياطي.
- مجلد بيانات التطوير `.desktop-dev` وملف `.env` غير مرفوعين إلى Git.
- «رقم تواصل المحل» في الإعدادات (`shop_phone`) هو رقم هاتف المحل المطبوع على الفاتورة فقط.
